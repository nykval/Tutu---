# Базы данных и справочники

## Две базы

В проекте есть две независимые базы:

| База | Файл или сервис | Для чего нужна |
|---|---|---|
| Общая | Cloudflare D1 `tutu-collections` | Рабочие данные всех пользователей |
| Локальная | `data/collections.sqlite3` | Изолированная разработка и проверка локального сервера |

Они не синхронизируются автоматически. Изменение локальной SQLite не влияет на D1.

## Базовый каталог

Начальные 200 географий и 101 тема находятся в:

- `data/catalog-seed.json` — единый редактируемый источник;
- `assets/js/catalog-data.js` — сгенерированная версия, которую может прочитать браузер без сервера.

После изменения JSON выполните:

```bash
python3 scripts/sync_catalog.py
```

Не редактируйте `catalog-data.js` вручную: следующее генерирование перезапишет изменения.

Cloudflare D1 хранит только созданные и изменённые элементы каталога. При загрузке фронтенд объединяет базовый каталог с ответом D1. Совпадение определяется по `id`, а версия из D1 побеждает.

## Таблицы Cloudflare D1

### `catalog_items`

Одна таблица для географий и тем.

| Поле | Значение |
|---|---|
| `id` | постоянный числовой идентификатор |
| `catalog` | `geographies` или `themes` |
| `name` | отображаемое название |
| `name_key` | нормализованное название для проверки дублей |
| `type` | тип географии или темы |
| `blocked_geography_ids` | JSON-массив запрещённых географий |
| `blocked_theme_ids` | JSON-массив запрещённых тем |

### `collections`

| Поле | Значение |
|---|---|
| `id` | идентификатор подборки |
| `key` | уникальный ключ всей конфигурации |
| `geography_id` | выбранная география |
| `theme_ids` | JSON-массив из 1–3 тем |
| `hotel_count` | ожидаемое число ссылок |
| `benefit_type` | `action`, `promocode` или `NULL` |
| `discount_percent` | процент выгоды или `NULL` |
| `created_at` | дата создания в UTC |
| `updated_at` | дата последнего изменения в UTC |

`key` строится из географии, отсортированных тем, количества отелей и выгоды. Он запрещает создавать две полностью одинаковые подборки.

Поля `created_at` и `updated_at` позволяют показать создание и последнюю правку. Отдельной таблицы аудита нет, поэтому промежуточные версии и авторы изменений не сохраняются.

### `hotel_links`

| Поле | Значение |
|---|---|
| `collection_id` | владелец ссылки |
| `position` | порядок ссылки в подборке |
| `url` | ссылка на отель |

При удалении подборки связанные ссылки удаляются каскадно.

## Локальная SQLite

Локальная база использует отдельные таблицы `geographies` и `themes`, но наружу локальный API возвращает такой же формат, как Worker. При первом запуске схема создаётся и наполняется из `catalog-seed.json`.

`data/collections.sqlite3` можно удалить только если локальные подборки больше не нужны: при следующем запуске файл будет создан заново из seed. Общая D1 от этого не изменится.

## Миграции

- `0001_initial.sql` создаёт исходную схему D1.
- `0002_catalog_blocks.sql` добавляет поля блокировок.

### Особенность текущего production

`0002_catalog_blocks.sql` был выполнен вручную через D1 Console. Колонки существуют, но запись `0002_catalog_blocks.sql` может отсутствовать в `d1_migrations`.

Поэтому команда автоматического применения всех миграций может попытаться добавить колонки повторно. Перед её запуском проверьте:

```sql
PRAGMA table_info(catalog_items);
```

Если `blocked_geography_ids` и `blocked_theme_ids` уже присутствуют, повторно выполнять `ALTER TABLE` нельзя.

## Резервирование

Перед ручным изменением production D1:

1. Откройте D1 → `tutu-collections` → **Time Travel**.
2. Запишите текущий bookmark или время.
3. Проверьте SQL сначала чтением схемы.
4. Выполняйте только одну понятную операцию за раз.
5. После изменения проверьте `/api/health` и `/api/bootstrap`.

Не храните в D1 пароли, персональные данные или закрытые токены.

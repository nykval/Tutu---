# Архитектура приложения

## Компоненты

### Фронтенд

Статическое приложение без сборщика и внешнего фреймворка. Начальная точка — `index.html`, логика — `assets/js/app.js`.

Фронтенд отвечает за:

- конструктор подборки;
- модальные окна географий, тем и блокировок;
- каталог сохранённых подборок;
- административный интерфейс справочников;
- предварительную проверку полей и конфликтов;
- локальный автономный режим через `localStorage`.

### Cloudflare Worker

`cloudflare-worker/src/index.js` — общий production API. Он является единственной точкой доступа фронтенда к D1 и Tutu MCP.

Worker отвечает за:

- чтение справочников и подборок;
- окончательную валидацию запросов;
- создание, редактирование и удаление подборок;
- сохранение блокировок;
- поиск отелей через Tutu MCP;
- CORS для разрешённых адресов фронтенда.

### Cloudflare D1

Общая SQLite-совместимая база `tutu-collections`. Подключена к Worker под именем `DB`.

### Tutu MCP

Worker вызывает `search_hotels` по адресу `https://mcp.tutu.ru/mcp`. Из ответа используются данные отелей и checkout-ссылки Tutu.

### Локальный сервер

`local_server/server.py` повторяет основной API поверх локальной SQLite. Он нужен для изолированной разработки и резервного запуска, но не участвует в production.

## Основные потоки

### Загрузка приложения

1. Браузер загружает `catalog-data.js` с базовыми географиями и темами.
2. Фронтенд вызывает `GET /api/bootstrap`.
3. Worker возвращает изменения справочников и общие подборки из D1.
4. Фронтенд объединяет базовый каталог и данные D1 по `id`. Запись из D1 имеет приоритет.

### Проверка подборки

1. Пользователь выбирает географию, темы, количество отелей и выгоду.
2. Фронтенд проверяет заполненность и известные блокировки.
3. `POST /api/lookup` повторно проверяет данные на сервере.
4. Worker строит стабильный ключ конфигурации и ищет точное совпадение.
5. Если точного совпадения нет, Worker возвращает до шести похожих подборок.

### Создание подборки

1. Пользователь добавляет нужное количество ссылок вручную или запускает автопоиск.
2. Worker проверяет формат, количество и уникальность ссылок.
3. Параметры записываются в `collections`, ссылки — в `hotel_links`.
4. Одинаковую конфигурацию нельзя сохранить второй раз благодаря уникальному `key`.

### Автоматический поиск отелей

1. Фронтенд передаёт даты, число гостей, географию, темы и требуемое количество.
2. Worker переводит поддерживаемые темы в фильтры Tutu MCP: удобства, звёзды, особенности номера.
3. Worker получает кандидатов постранично, удаляет дубли и проверяет специальные сценарии.
4. Отели сортируются по рейтингу и числу отзывов.
5. Фронтенд получает готовые ссылки, но сохраняет подборку только после действия пользователя.

### Блокировки

Блокировка может быть задана:

- у географии против темы;
- у темы против географии;
- у темы против другой темы.

Проверка симметрична: сочетание запрещено независимо от того, в карточке какого элемента было создано правило. Фронтенд блокирует выбор заранее, Worker повторяет проверку перед поиском и сохранением.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка доступности Worker |
| `GET` | `/api/bootstrap` | Справочники, возможности сервера и подборки |
| `POST` | `/api/lookup` | Поиск точной и похожих подборок |
| `POST` | `/api/collections` | Создание подборки |
| `PUT` | `/api/collections/:id` | Замена ссылок подборки |
| `DELETE` | `/api/collections/:id` | Удаление подборки |
| `POST` | `/api/hotel-search` | Поиск отелей через Tutu MCP |
| `POST` | `/api/geographies` | Создание географии |
| `PATCH` | `/api/geographies/:id` | Изменение географии и её блокировок |
| `POST` | `/api/themes` | Создание темы |
| `PATCH` | `/api/themes/:id` | Изменение темы и её блокировок |

## Похожие подборки

Текущий скоринг:

| Совпадение | Баллы |
|---|---:|
| Та же география | 5 |
| Каждая общая тема | 3 |
| То же количество отелей | 1 |
| Та же выгода | 1 |

Показываются шесть результатов с наибольшим баллом; при равенстве выше находится более недавно обновлённая подборка.

## Границы ответственности

- Фронтенд отвечает за удобство и раннюю обратную связь.
- Worker является источником истины для правил и валидации.
- D1 отвечает только за хранение, но не содержит бизнес-логику.
- MCP отвечает за актуальный поиск предложений, но не сохраняет подборки.

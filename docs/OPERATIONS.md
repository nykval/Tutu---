# Эксплуатация и публикация

## Что опубликовано

- Worker: `tutu-collections-api.skorokirzhaboy.workers.dev`.
- D1: `tutu-collections`.
- D1 binding: `DB`.
- Разрешённый origin фронтенда: `https://nykval.github.io`.
- Репозиторий: `https://github.com/nykval/Tutu---.git`.

## Публикация фронтенда

Фронтенд состоит из статических файлов. При публикации должны быть загружены вместе:

- `index.html`;
- папка `assets`;
- при необходимости документация и остальные файлы репозитория.

После публикации проверьте в браузере:

1. открывается конструктор;
2. загружаются географии и темы;
3. видны сохранённые подборки;
4. открываются модальные окна;
5. отсутствуют ошибки загрузки CSS, JS и изображений.

## Обновление Worker через Cloudflare Dashboard

1. Откройте **Workers & Pages → tutu-collections-api**.
2. Убедитесь в разделе Bindings, что `DB` указывает на `tutu-collections`.
3. Нажмите **Edit code**.
4. Замените код содержимым `cloudflare-worker/src/index.js`.
5. Нажмите **Deploy**.
6. Откройте `https://tutu-collections-api.skorokirzhaboy.workers.dev/api/health`.
7. Ожидаемый ответ: `{"status":"ok"}`.
8. Затем обновите приложение и проверьте чтение каталога.

Изменение кода Worker не требует повторного выполнения SQL, если схема базы не менялась.

## Изменение D1 через Dashboard

1. Откройте **Storage & databases → D1 → tutu-collections → Console**.
2. Перед записью проверьте нужную таблицу командой `PRAGMA table_info(...)`.
3. Не создавайте новую базу вместо существующей.
4. Не удаляйте таблицы и колонки без отдельного плана восстановления.
5. После изменения проверьте Worker и приложение.

Состояние миграции блокировок описано в [`DATABASE.md`](DATABASE.md#особенность-текущего-production).

## Запуск локальной версии

1. В `assets/js/config.js` временно задайте пустой `apiBaseUrl`.
2. Запустите `Запустить подборки.command`.
3. Работайте по адресу `http://127.0.0.1:8765`.
4. После проверки верните production URL в `config.js`, если собираетесь публиковать фронтенд.

Локальный сервер принимает запросы только с `127.0.0.1` и `localhost` на своём порту.

## Проверка перед выпуском

- [ ] JavaScript проходит `node --check`.
- [ ] Тесты локального API проходят.
- [ ] `config.js` указывает на правильный Worker.
- [ ] Binding `DB` не изменён.
- [ ] Миграции не запускаются повторно вслепую.
- [ ] Существующие подборки видны после обновления.
- [ ] Создание, изменение и удаление проверены на тестовой подборке.
- [ ] Блокировки работают и на фронтенде, и после серверного запроса.
- [ ] Автопоиск возвращает реальные ссылки Tutu.

## Диагностика

### Приложение показывает, что сервер недоступен

1. Откройте `/api/health` Worker.
2. Проверьте адрес в `assets/js/config.js`.
3. Проверьте Worker → Bindings → `DB`.
4. Посмотрите Workers Logs в Cloudflare.

### Справочники есть, а D1 `catalog_items` пуст

Это штатно: основной каталог встроен во фронтенд. D1 хранит только добавления и изменения.

### Блокировки не появляются

1. Проверьте, что `/api/bootstrap` возвращает `supportsBlocks: true`.
2. Проверьте наличие двух колонок через `PRAGMA table_info(catalog_items)`.
3. Убедитесь, что опубликована актуальная версия Worker.

### После обновления пропали стили или изображения

Проверьте, что вместе с `index.html` опубликована вся папка `assets` с сохранением структуры.

## Откат

- Код Worker: откройте **Deployments** и верните предыдущую рабочую версию.
- D1: используйте **Time Travel** только после проверки точки восстановления.
- Фронтенд: верните предыдущий commit в GitHub и повторно опубликуйте Pages.

Откат Worker не откатывает D1 автоматически, и наоборот.
